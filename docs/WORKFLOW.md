# Start a task with huguesStack

Read this guide in under five minutes. For current results and prerequisites,
open [support](support.md); for their receipts, open the
[evidence index](evidence-index.md). The package is the `0.1.0-rc.2` prerelease candidate. Read the
[RC notes](RELEASE-0.1.0.md) for current evidence and remaining gaps.

## Give the host a goal and a check

In a Claude Code session that has loaded this checkout, invoke
`/hugues-stack:hugues-mode`. Follow [host loading](host-loading.md) for the
session-local loading method and its observed limits.

In Codex, use the documented, coordinator-authorized manual project-skill path
and `$hugues-mode`, or directly read the discovered skill when its invocation
tool is unavailable. Record which fallback you used. Native Codex installation
and invocation remain unverified; installation is outside the current authority.

Supply the consumer repository, outcome, permitted changes and a way to check it:

```text
In the authorized consumer checkout, fix the shared discount boundary.
Preserve existing changes. Show the failing case turning green in common tests
and prove the native caller on Android and iOS. Report blocked targets separately.
```

To inspect the proposed work first, request **route preview**. The mode reads a
playbook and displays its steps, domain and required proof, then stops before
delegation or consumer commands. A preview proves planning behavior only. The retained 16-case/87-step host
previews tested historical RC1 bytes; the changed RC2 playbooks and 79 plugin
files have no fresh loading or workflow-adherence observation.

## Follow the selected playbook

Check that the selected route and todo list match your request. The coordinator
investigates and delegates each implementation or fix round to a fresh worker.
Read the selected shipped tool in full before use. The playbooks link directly
to research and design tools. Bug routes preserve a cheap regression RED before
a fresh production worker, or an explicit impractical-seam reason alongside the
original runtime failure. For an existing bounded proof recipe, the coordinator
uses `maintain-verification-skill` for its source wave and live pass; new recipes
use the generator. Recurring mistake classes use `correct` once repeated evidence
exists. These handoffs retain consumer authority and target proof obligations.

Give that worker its assigned paths, current instructions, preservation rules
and completion check. Keep consumer work in its own repository.

Before running mobile proof, have the coordinator read the consumer's current
instructions and existing verification recipe. Agree on the target artifact,
journey and permitted operations. A proposed recipe or passing framework test
does not authorize consumer edits, device runs, dependency downloads, settings
changes or external transmissions. If a prerequisite is blocked, record its
reason and continue independent authorized work.

| Domain | Proof to request for the claimed task |
|---|---|
| Swift/iOS | Relevant XCTest, simulator build and a driven user path |
| Kotlin/Android | Relevant tests, demoDebug assembly and emulator user path |
| KMP shared logic | Common tests and a native caller on each claimed target |
| CMP shared UI | Android and iOS screens, plus semantics or text-scaling checks |

Read [mobile lanes](../plugin/skills/hugues-mode/references/mobile-lanes.md) for
the selected domain and [evidence guide](../plugin/skills/hugues-mode/references/evidence-guide.md)
before collecting proof. Respect the consumer's required build and device tools.

## Inspect the result and resume safely

Require artifact/revision bindings, exact commands, test identities and counts,
failed attempts and explicit gaps. Distinguish authored instructions, static
checks and observed behavior. Treat skips as excluded assertions; successful
same-artifact/condition retries retain flaky outcomes. Keep separate changed-condition
attempts visible. Reopen retained reports and captures after the
authorized cleanup; remove only task-owned state within the agreed scope.

For a new PR, require independent **GPT-6 Astra High** review, adjudicated fixes,
tests and re-review against the final head. Implementation workers inherit the
parent model. If the host cannot select Astra High, report the review blocker
without substituting another model or effort. Record the accepted reviewer settings and exact reviewed SHA;
same-host review establishes process independence. Keep historical cross-host
Claude receipts separate. Prepare a draft PR for owner review; merge and release
remain separate decisions.

Before compaction or a pause, use
[pause-safely](../plugin/skills/hugues-mode/playbooks/pause-safely.md) to retain the
worktree/head, assigned paths, evidence locations, completed checks, blockers and
next action. Resume with
[session-pickup](../plugin/skills/hugues-mode/playbooks/session-pickup.md), reread
current instructions and reconcile the actual Git state before continuing.

The owner's first-release checkpoint accepts an observed task per domain **or a
labelled reason**. It does not convert a blocked cell into support. Consult the
[plan](PLAN.md) before proposing that checkpoint; the target remains
**9 October 2026, end of day GMT+7**.

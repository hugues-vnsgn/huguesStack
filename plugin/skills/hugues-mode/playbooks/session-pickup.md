# Session pickup

source: Adapted from pstack 0.15.9 at `e43c7ee26e0038c6c1fa8380dd34ce86ff94cb2a`, `pstack/skills/poteto-mode/playbooks/session-pickup.md`; MIT notice in PSTACK-LICENSE.

Own the resume point. Read the prior trail before repeating work.

## Steps

1. Locate the supplied task trail, evidence folder or branch within this project. Read its summary and last decisions first; inspect older details only as needed. Keep unrelated project transcripts private. A fresh read-only subagent may reduce a long authorized trail to cited decisions.
2. Reconstruct branch, worktree, actual landed changes, pending todos, authority, decisions and evidence paths. Compare the trail to git status and history without discarding local edits.
3. Compare completed and pending work and name the resume point. Reuse retained evidence for the exact artifact and target it tested; rerun a check only when changed inputs, missing artifacts or a disputed claim require it.
4. Route the pending task to its matching playbook, preserving skipped items and reasons. State whether to continue implementation, deliver a recommendation, adjudicate a conclusion or diagnose a failed run; this route ends at that handoff.
5. Verify inherited completion claims against the goal and actual artifacts before reporting them. The routed playbook owns new checks and fresh implementation delegation; disclose evidence that cannot be inspected or reproduced.

**Reply:** prior stop, inherited facts, resume point, reruns with reasons and outcome.
